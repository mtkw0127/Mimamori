# プロダクト仕様

## 1. コンセプト

使っていないスマートフォンを「見守りカメラ」にするアプリ。
ペット・子ども・赤ちゃんの様子などを、**家の中の別の部屋から**手元の端末で確認できる。

映像は同じ Wi-Fi 内の端末間で直接（P2P）送るため、映像データが家の外に出ることも、サーバーに保存されることもない。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| Recorder | カメラで撮影し映像を配信する端末 |
| Viewer | Recorder の映像を視聴する端末 |
| ペアリング | OTP を使って Recorder と Viewer を初めて紐付ける手続き |
| OTP (One-Time Password) | ペアリング時に Recorder の画面に表示される使い捨てのパスワード |
| ペアリング済み Viewer | ペアリングに成功し、Recorder に登録されている Viewer |
| 破棄 (Revoke) | Recorder がペアリング済み Viewer の接続権限を取り消すこと |
| 同一ネットワーク | 同じ Wi-Fi ルーターに繋がっている状態 |

## 3. 想定ユースケース

1. **初回セットアップ**
   1. ユーザーは古い端末 A を Recorder として子ども部屋に設置し、撮影を開始する。
   2. A の画面で「Viewer を追加」を押すと OTP が表示される。
   3. 同じ Wi-Fi に繋がった普段使いの端末 B で Viewer を起動すると、A が一覧に表示される。
   4. A を選んで OTP を入力すると、ペアリングが成功し、B に A の映像が表示される。
2. **2 回目以降の視聴**
   - B で Viewer を開くと、ペアリング済みで撮影中の A が表示され、選ぶだけで映像が見られる（OTP 入力不要）。
3. **Viewer の破棄**
   - 家族の端末の権限を外したい／端末を手放すときに、A の「Viewer 一覧」から該当 Viewer を削除する。
   - 視聴中であれば即座に切断され、以降は再ペアリングしない限り接続できない。

## 4. 機能要件

### 4.1 Recorder

| ID | 要件 |
| --- | --- |
| R-1 | カメラ映像の撮影を開始／停止できる |
| R-2 | 前面／背面カメラを切り替えられる |
| R-3 | ペアリング用の OTP を発行し、画面に表示できる |
| R-4 | OTP には有効期限があり、一度使用されたら無効になる |
| R-5 | ペアリング済み Viewer の一覧を表示できる（端末名・ペアリング日時・最終接続日時） |
| R-6 | ペアリング済み Viewer を破棄できる。接続中なら即時切断する |
| R-7 | 撮影中は同一ネットワーク内に自分の存在を告知し、Viewer からの接続を待ち受ける |
| R-8 | 撮影中であることが画面上で明確に分かる（プライバシー配慮） |

### 4.2 Viewer

| ID | 要件 |
| --- | --- |
| V-1 | 同一ネットワーク内の Recorder を自動で見つけて一覧表示できる |
| V-2 | 一覧から Recorder を選び、OTP を入力してペアリングできる |
| V-3 | ペアリング済み Recorder を選んで、OTP なしで接続できる |
| V-4 | Recorder の映像をリアルタイムで表示できる |
| V-5 | ペアリング済み Recorder が見つからない（撮影停止中・別ネットワーク）ことを表示できる |
| V-6 | 破棄された場合は、その旨を表示しローカルのペアリング情報を削除する |

### 4.3 スコープ外

- **家の外（別ネットワーク）からの視聴**。サーバー・STUN・TURN を使わない設計のため対象外とする。

### 4.4 検討中（v1 スコープ外候補）

- 音声（マイク）の送信
- Viewer から Recorder への音声（トーク機能）
- 動体検知と通知
- 録画
- QR コードによるペアリング
- 複数 Viewer の同時視聴（→ 発熱・バッテリーとのトレードオフ。[architecture.md](architecture.md#7-省電力発熱対策) 参照）

## 5. 非機能要件

### 5.1 バッテリー・発熱

Recorder は長時間（数時間〜常時）稼働させる前提のため、最重要の非機能要件とする。

- Viewer が接続していない間は、カメラを止め、映像のエンコード・送信を行わない。
- 解像度・フレームレート・ビットレートは「見守り」に十分な控えめな値をデフォルトにする。
- 端末の温度状態を監視し、高温時は自動で画質を落とす。
- 充電しながらの運用を推奨し、アプリ内でも案内する。

詳細は [architecture.md](architecture.md#7-省電力発熱対策) を参照。

### 5.2 セキュリティ・プライバシー

- 同じ Wi-Fi に繋がっていても、ペアリングしていない端末（来客・同居人など）は映像を視聴できない。
- 映像は WebRTC により暗号化（DTLS-SRTP）されて送信される。
- 映像は家の外に出さず、どこにも保存しない。

詳細は [security.md](security.md) を参照。

### 5.3 接続性

- 同一ネットワーク内であれば、IP アドレスの入力などの設定なしで接続できること。
- 接続までの時間は数秒以内を目標とする。
- Wi-Fi の再接続などで一時的に切れても、自動で再接続できること。

## 6. 制約

- Recorder と Viewer は同じネットワーク（同じルーター配下）に繋がっている必要がある。
- ルーターの「AP アイソレーション（プライバシーセパレーター）」やゲスト Wi-Fi など、端末同士の通信を遮断する設定では利用できない。ヘルプで案内する。
- メッシュ Wi-Fi・中継器環境でも、同じネットワークであれば利用できる想定（要実機検証）。
